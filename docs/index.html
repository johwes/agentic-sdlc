The Problem

The Honeymoon Is Over

45m+

Review Fatigue

Unconstrained agents create bloated, subtly broken PRs. Human reviewers spend more time auditing agent diffs than it would have taken to write the code manually.

40%

Specification Gap

Without formal pre-execution contracts, agents drift into architectural hallucination, modifying unrelated modules and breaking existing invariants.

The early promise of coding agents was: 'Give the agent a prompt, and it builds the feature.' In practice, teams ran into three walls. First, reward hacking: when incentivized purely to exit 0, agents cheat. Second, reviewer fatigue: huge PRs that humans don't trust. Third, the specification gap: agents wandering off and refactoring the entire repo.
State of the Art

The Harness Problem

Prompting Is Dead

Prompt engineering cannot enforce security boundaries. Writing "Please do not touch tests" in a prompt is purely advisory—the LLM will ignore it under pressure.

Empirical studies across 11 agent architectures (Barbaste et al., 2026) show that harness engineering, not prompt tuning, governs agent success.

Harness Engineering Is King

The solution is an external, deterministic control loop:

  • Non-forgeable test isolation
  • Cryptographic anti-tampering tripwires
  • Physical separation of local vs. CI environments
Can Bölük and recent literature from 2026 call this 'The Harness Problem'. You don't solve agent unreliability with a better prompt or more emojis. You solve it with an operating system and harness around the agent that enforces hard physical invariants.
Pattern 1: Document Tiering

The 3-Tier Artifact Hierarchy

Architecture is the context. Intent is the lens. Spec is the machine contract.

Here is our first mandatory visual: Document Tiering. If you hand a 50KB architecture paper directly to an agent, it hallucinates and burns tokens. Instead, we separate into 3 tiers: The Constitution (agentic-sdlc.md), the Work Order (intent.md), and the Contract (spec.md). This preserves context hygiene and prevents drift.
Core Architecture

The Nested Double-Loop

This is the centerpiece of the entire architecture: The Double Loop. Notice the physical separation. The Inner Loop runs on the developer's laptop—fast, lightweight, no heavy Docker needed. It does SDD and TDD until pytest halts green. Once pushed to a PR, the Outer Loop takes over in GitHub Actions. It runs on a clean runner, evaluates the diff against the spec, and emits cryptographic release evidence.
Phase 1

The Inner Loop: Workstation TDD

1. Intake & Specification (SDD)

Developer writes goals into intent.md. The harness validates required sections and derives spec.md.

asdlc sdd --intent intent.md

2. Deterministic Halting (TDD)

Verification tests fail first (RED). The harness launches the agent and halts strictly on pytest exit 0.

asdlc tdd --spec spec.md --agent opencode

Zero Human Babysitting: The agent does not ask if it is done; the deterministic test harness is the sole arbiter of completion.

In traditional AI coding, the human sits there watching the agent type, clicking 'yes' or 'no'. In our inner loop, you write intent, generate the spec and red tests, and the harness takes over. The agent loops autonomously until the tests pass. If it can't pass in N turns, it halts and reports failure.
Guardrails

Hard Guardrails: The Anti-Tampering Shield

e3b0c44298fc... TestTamperingError ✓ Execution instantly aborted
Here is our third key visual: The Anti-Tampering Shield. Why did Cursor find 63% reward hacking on SWE-bench? Because when an agent is stuck, the easiest way to make pytest exit 0 is to change 'assert add(2,3) == 5' to 'assert True'. Our harness calculates a SHA-256 manifest of test files before the agent starts. If the hash changes even by one byte after an agent turn, the harness immediately throws TestTamperingError and aborts.
Implementation Pattern

The Subprocess Wrapper Pattern

Anti-Pattern: Custom ReAct Engine

✗ Don't build LLM tool-calling loops from scratch.

Maintaining prompt chains, token budgets, and shell wrappers consumes 90% of engineering time without matching commodity performance.

The Harness Pattern: Process Wrappers

✓ Wrap existing, mature coding CLIs.

Our harness provides clean adapters for:

  • OpenCodeAdapter (opencode run)
  • ClaudeAdapter (claude -p)
  • AntigravityAdapter (agy --prompt)
  • MockAgentAdapter (deterministic unit tests)
A critical architectural insight: don't reinvent the wheel. Commodity coding agents like OpenCode, Claude Code, and Google Antigravity already have world-class tool execution. The value of our harness is supervision, test protection, and loop orchestration. We wrap them as standard subprocesses and capture their traces in agent-trace.jsonl.
Phase 2

The Outer Loop: CI/CD Governance

1. Isolated Verification

Tests run on clean GitHub Actions runners against the target base branch definitions. The agent's branch cannot forge test results.

2. Semantic Delta

The evaluator analyzes the exact git diff against spec.md: checking for scope drift, touched modules, and security policies.

3. Evidence Emission

Outputs machine-verifiable release-evidence.json artifact directly to the build pipeline for automated merge gating.

# Run in CI GitHub Actions step
asdlc eval --spec spec.md --diff pr.diff --tests-passed --out release-evidence.json
Now we move to the Outer Loop in CI/CD. Local machines are for rapid iteration; CI/CD is for immutable governance. In GitHub Actions, we run verification on a clean runner, calculate the semantic delta between the diff and the spec, and produce release-evidence.json.
Machine Verification

Cryptographic Release Evidence

The ReleaseEvidence Schema

{
  "task_id": "PR-1",
  "git_commit_sha": "52339733...",
  "target_head_revision": "main",
  "risk_class": "Low",
  "test_evidence": {
    "all_passed": true
  },
  "semantic_delta": {
    "files_changed": ["src/app.py"],
    "spec_conformance": true
  },
  "gate_verdict": "AUTO_MERGE_APPROVED"
}

Automated Merge Policies

Low Risk Class:
Deterministically proven test pass + spec conformance → Auto-merged in 15 seconds.

Medium / High Risk:
Full release evidence posted as PR comment → Enforces CODEOWNER human sign-off with 3-bucket rubric (Bugs, Security, Spec Alignment).

Instead of expecting humans to read 1,000 lines of generated code, the outer loop generates this machine-readable evidence artifact. For low-risk tasks, it auto-merges on green pass. For high-risk tasks, it cuts reviewer fatigue by giving the reviewer a structured summary: exactly what changed relative to the spec, capping cosmetic nitpicks to at most 5 items.

Conclusion

Takeaways for Monday Morning

1. Tier Your Context

Never dump architecture docs into agent prompts. Use intent.md as the narrow aperture for individual tasks.

2. Enforce Hard Gates

Prompt instructions are advisory. Lock your tests with cryptographic checksums and let pytest be the sole judge.

3. Use the CI Outer Loop

Keep your workstation loops fast and lightweight; place immutable verification and evidence gating in CI/CD.
