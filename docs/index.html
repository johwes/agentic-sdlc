Software Architecture 2026

The Agentic SDLC
Control Plane

Price Tradeoffs · Enforce Mechanically · Ration Attention

johwes/agentic-sdlc

Welcome everyone. Autonomous coding agents are here, and the question is no longer whether they write code — it is how we govern what they do. This talk proposes a control plane with four properties: price every tradeoff explicitly, enforce properties mechanically rather than by instruction, separate every judgment so nothing verifies itself, and ration human attention by risk. Spec-driven, test-driven, and evaluation-driven development are instantiations of that plane — not the argument itself. Three acts: what it is, what it costs, how to build it.
The Problem

Autonomy Without Governance Relocates Cost

Tokens

Unbounded Burn

Agent loops with no halting condition consume millions of tokens wandering — spend with no verdict.

Minutes

Review Load

Every generated line must be read by someone. Per-reviewer load has doubled while substantive review thins out.

Risk

Silent Failures

Suppressed review reappears as production incidents. Agents that grade their own work pass their own tests.

Measured: agents hit the right file ~80% of the time but the right function only 27% (arXiv:2511.00197) — unguided autonomy drifts.

The early promise was 'give the agent a prompt, and it builds the feature.' What actually happens: costs don't disappear, they relocate — token burn on the agent side, review load on the human side, incident risk in production. Governing agentic development means pricing each of those ledgers explicitly instead of discovering them after the merge. One measured data point on drift: file-level localization near 80%, function-level only 27% — the agent finds the neighborhood, not the address.
The Answer

A Control Plane, Not a Prompt

1. Price Tradeoffs

Every control paid for in tokens, human minutes, time, or residual risk. Measure it here — never assume the price.

2. Enforce Mechanically

Gates that terminate in mechanisms, never messages. Instructions advise; only enforcement governs.

3. Separate Judgment

No self-verification at any layer: generator vs evaluator, test author vs code author, agent proposes vs human disposes.

4. Ration Attention

Ceremony proportional to blast radius. Low risk flows fast; high risk earns human review. Never uniform.

Four properties, and they compose the whole talk. Price: every control has a cost in two currencies — adopt nothing unpriced. Enforce: if it ends in a prompt, it is advice, not governance. Separate: anything that grades its own work will pass itself. Ration: human attention is the scarcest resource — spend it by risk, not by habit. SDD, TDD, and EDD are instantiations of this plane, used where they earn their place.
Pattern 1: Document Tiering

The Loop, Concretely

The SDD contract: intent bounds scope, spec defines done, tasks sequence the work — nothing downstream contradicts the tier above it.

Concretely, the loop starts with tiered documents, not prompts. The constitution sets org principles once; each task gets a narrow intent aperture; the spec is the machine contract with acceptance criteria. Nothing downstream — tasks, tests, code — may contradict the tier above it. This preserves context hygiene and prevents drift.
Core Architecture

The Nested Double-Loop

This is the centerpiece: the double loop as the instantiation of the control plane. The inner loop runs on the developer's machine — fast, lightweight, no heavy Docker needed — intent to spec to RED test to agent to GREEN halt. The outer loop takes over at the PR in CI: clean runner, diff evaluated against the spec, machine-verifiable release evidence. Diagram first, mechanics next.
Enforcement

Enforcement, Not Instruction

A prompt saying "don't touch tests" is advice. A hash manifest checked after every agent turn is enforcement.

Enforcement, not instruction — the doctrine in one picture. When an agent is stuck, the easiest way to make pytest exit 0 is rewriting the test instead of fixing the code. Our harness fingerprints test files before the agent starts; a one-byte change aborts the run with TestTamperingError. The inner loop also halts on bounded turns and verified RED — the controller, not the agent, decides when work stops.
Tradeoffs

The Balance Sheet

Tokens ↔ Review

Bounded iteration and evidence cost tokens — and convert into fewer review minutes. Suppress review instead, and the cost reappears as incidents.

Rigor ↔ Speed

Seeds, holdouts, and ensembles buy assurance at the price of time-to-green. Mismatch rigor to risk and you pay up to 25× for nothing.

Autonomy ↔ Assurance

Removing the human removes review cost — payable only in reversibility and monitoring. Buy mechanisms (rollback, canary), not review theater.

Doctrine: price every control in both currencies before adopting it.

Every governance choice moves cost between ledgers — tokens, human minutes, time, residual risk. This discipline is old: quality economics priced prevention against failure decades ago; SRE error budgets couple velocity to reliability through one number. What's new is applying it across human and machine actors, with policy-set slider positions instead of fixed rules. The takeaway for Monday: never adopt a control without pricing it twice.
Evidence

What Measurement Shows

Localization, Scoped

Agents hit the right file ~80% but the right function 27% (arXiv:2511.00197) — and at the frontier the bottleneck moves to edit quality, which outcome-only evals miss entirely.

Two Threat Classes

Benchmark-leakage hacks (mined fixes, upstream lookup) dominate public evals — and mostly don't transfer to private repos. Test tampering and vacuous tests do.

Review Economics

Per-reviewer load doubled while substantive review thins; trust does not accumulate per-PR. Trajectory quality is cost control.

Evidence, with scoping attached — because unscoping is how numbers mislead. Localization first: file-level is largely solved, function-level lags, and frontier failures are now edit-quality, invisible to pass/fail grading. Threats second: separate what pollutes benchmarks from what threatens deployments, and govern the latter. Economics third: review load is the binding constraint, so everything that shrinks it — small diffs, good evidence — is cost control.
Honesty

Open Disputes, 60 Seconds

Ritual Skepticism

Does instructing TDD improve outcomes? Measured effect: near zero, at 3–8× token cost. Our answer: enforce properties, not ritual.

Test-Authorship Limits

Agent-written tests barely move outcomes; 11.58% assert nothing. Oracles and hermeticity decide — not volume.

Metric Boundaries

Coverage and mutation inform regression health, not bug-detection proof, on possibly-buggy code. Scope every metric.

Each dispute ships with its mind-changer: the evidence that would overturn our stance.

Sixty seconds of honesty, and the highest trust-per-minute in the deck. The field genuinely disputes whether in-agent TDD rituals help, whether agent-written tests assure anything, and whether our favorite metrics transfer. Our positions: enforce checkable properties instead of ritual; oracles and hermeticity over test volume; scope every metric to what it was validated for. Each stance names the evidence that would change our mind — ask us about any of them afterwards.
Choices

Inner-Loop Choices

Sealed TDD vs Design-First

Enforce RED proof, sealed tests, and bounded turns — or lead with upfront design and verify after. Never instruct ritual without verification.

Budgets & Sandboxing

Turn, time, and token caps per run; sandbox rungs from subprocess to containers. The controller halts — the agent never decides it is done.

Test-Authorship Ladder

Single agent, human-confirmed contract tests, or dual-agent with filesystem separation. Stronger oracle claims cost more — spend accordingly.

Commodity Adapters

Wrap existing CLIs (opencode, claude, agy) as subprocesses; capture traces. Don't build a ReAct engine.

asdlc tdd --spec spec.md --test-file tests/test_spec.py --agent opencode
Implementation choices, inner loop — each a slider, not a doctrine. Sealed TDD or upfront design first: pick by task shape, but whichever you pick, the gates are non-negotiable. Budgets bound cost; sandboxing bounds blast radius; the authorship ladder prices oracle strength. Wrap commodity agents rather than building engines — supervision is our value-add, not tool execution.
Choices

Outer-Loop Choices

Gates → Judges → Review

Deterministic checks gate every merge; trajectory metrics must not regress; calibrated judges advise; humans decide high-risk cases. N-seed minima keep noise from becoming verdicts.

asdlc eval --spec spec.md --diff pr.diff --tests-passed

And the economics are budgets, not boasts: bounded inference, sub-minute gates, review minutes tracked like any other cost.
Conclusion

Takeaways for Monday Morning

1. Tier Your Context

Never dump architecture docs into agent prompts. Use intent.md as the narrow aperture for individual tasks.

2. Price Controls Twice

Every gate costs tokens, minutes, or risk. Adopt nothing unpriced — measure it here, never assume the price.

3. Enforce, Don't Instruct

Prompts advise; mechanisms govern. Seal the tests, verify RED, halt on budgets, gate the merge on evidence.
