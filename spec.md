## 2. System Architecture & State Machine

`asdlc` implements the nested-loop lifecycle defined in [§1.2.2 of agentic-sdlc.md](file:///var/home/jwesterl/Downloads/opencode/agentic-sdlc/agentic-sdlc.md#L91), physically separated into a **Local Inner Loop (Developer Workstation)** and a **Remote Outer Loop (CI/CD / GitHub Actions)**.

### State Transitions

```
               [LOCAL INNER LOOP]                             [REMOTE OUTER LOOP]
  ┌───────────┐         ┌───────────┐
  │ INTENT    ├────────►│ SPECIFIED │
  └───────────┘ (SDD)   └─────┬─────┘
                              │ (Test Gen)
                              ▼
                        ┌───────────┐
                        │   TESTS   │ (RED)
                        │ GENERATED │
                        └─────┬─────┘
                              │
                    ┌─────────▼─────────┐
             ┌─────►│  AGENT ITERATING  │◄────┐
             │      └─────────┬─────────┘     │
             │ (Fail)         │               │ (Fail)
             └─────── [pytest exit 0?]        │
                              │ (Pass - GREEN)│
                              ▼               │
                        ┌───────────┐         │
                        │ INTEGRATED│         │
                        │ (Committed│         │
                        └─────┬─────┘         │
                              │ git push / PR │
                              ▼               │
                        ┌───────────┐         │
                        │ CI REVIEW ├─────────┘
                        │  PENDING  │ (Semantic / Eval Failure)
                        └─────┬─────┘
                              │ (LLM Judge + Gold Test Pass)
                              ▼
                        ┌───────────┐
                        │ RELEASE   │ (release-evidence.json)
                        │ APPROVED  │
                        └───────────┘
```

## 3. Directory Layout & Artifact Locations

A repository governed by `asdlc` adopts the following layout:

```text
.
├── intent.md                     # Root human intake artifact
├── spec.md                       # Derived technical specification
├── .asdlc/                       # Harness operational state & traces (gitignored)
│   ├── state.json                # Current harness lifecycle state
│   ├── test_manifest.json        # Test signatures & checksums for tampering detection
│   └── agent-trace.jsonl         # Intercepted agent execution logs
├── src/                          # Application source code generated by agent
├── tests/
│   └── test_spec.py              # Deterministic verification tests (RED -> GREEN)
└── .github/
    └── workflows/
        └── agentic_outer_loop.yml # Outer loop CI evaluation pipeline
```

## 4. CLI Interface Specification

The `asdlc` tool is installed as a Python package providing the `asdlc` CLI entrypoint:

### Commands

#### 1. `asdlc init`
Initializes a new `asdlc` project scaffold.
- **Flags**:
  - `--dir <PATH>`: Target root directory (default: `.`)
- **Behavior**:
  - Creates `.asdlc/` directory.
  - Initializes `.asdlc/state.json` with status `INITIALIZED`.
  - Creates baseline `.gitignore` entry for `.asdlc/`.

#### 2. `asdlc sdd`
Executes Specification-Driven Development intake.
- **Flags**:
  - `--intent <FILE>`: Path to `intent.md` (default: `intent.md`).
  - `--out <FILE>`: Path for derived specification (default: `spec.md`).
- **Behavior**:
  - Validates `intent.md` existence and required sections (`Problem`, `Scope`, `Acceptance Criteria`).
  - Transitions state to `SPECIFIED`.

#### 3. `asdlc tdd`
Executes the Test-Driven Development inner loop.
- **Flags**:
  - `--spec <FILE>`: Specification file (default: `spec.md`).
  - `--test-cmd <CMD>`: Deterministic test command (default: `pytest tests/test_spec.py`).
  - `--allow-green`: Allow execution if tests already pass initially (default: False).
  - `--agent <NAME>`: Coding agent adapter (`mock`, `opencode`, `claude`, `antigravity`; default: `mock`).
  - `--max-turns <INT>`: Maximum agent retry turns before halting (default: 5).
  - `--timeout <INT>`: Subprocess execution timeout in seconds (default: 180 or `ASDLC_TIMEOUT`).
- **Behavior**:
  1. Computes SHA-256 hash of `tests/test_spec.py` and records in `.asdlc/test_manifest.json`.
  2. Runs `--test-cmd`. Verifies that tests initially fail (**RED**). If tests already pass, halts with `InitialTestsAlreadyPassingError` (exit code 3) unless `--allow-green` is specified.
  3. Launches agent adapter subprocess targeting implementation code in `src/` with enforced execution timeout.
  4. Intercepts stdout/stderr and streams structured entries into `.asdlc/agent-trace.jsonl`.
  5. **Anti-Tampering Gate**: Re-verifies SHA-256 hash of `tests/test_spec.py`. If hash changed, halts immediately with `TestTamperingError` (exit code 2).
  6. Re-executes `--test-cmd`.
  7. If exit code is 0 (**GREEN**), transitions state to `INTEGRATED` and exits 0.
  8. If exit code is non-zero, increments turn counter and loops back to step 3. If `--max-turns` exceeded, transitions state to `ABORTED` and exits with code 1.

#### 4. `asdlc run`
Composite command executing the full inner loop pipeline:
```bash
asdlc run --intent intent.md --agent <agent_name>
```
Sequence: `init` (if needed) $\to$ `sdd` $\to$ `tdd`.

#### 5. `asdlc eval`
Outer-loop evaluator invoked by CI/CD (GitHub Actions / Tekton).
- **Flags**:
  - `--spec <FILE>`: Specification file (default: `spec.md`).
  - `--diff <FILE_OR_REF>`: Git diff file or base git ref (e.g. `origin/main...HEAD`).
  - `--out <FILE>`: Path to write `release-evidence.json` (default: `release-evidence.json`).
  - `--allow-test-changes`: Permit modifications to protected `tests/` directory (default: False).
  - `--judge-mode <MODE>`: `deterministic` (default) or `llm`.
- **Behavior**:
  - Generates `semantic_delta` summarizing lines changed and modules touched.
  - **Protected Path Integrity Guard**: Checks `files_changed`. If any modified file is within `tests/` and `--allow-test-changes` is False, sets `gate_verdict = "REJECTED"`, logs security violation, and rejects auto-merge.
  - Evaluates diff against `spec.md` constraints using 3-bucket rubric (Bugs, Security, Spec Alignment).
  - Emits canonical `release-evidence.json` conforming to the schema in Section 5.

  "title": "ReleaseEvidence",
  "type": "object",
  "required": [
    "task_id",
    "git_commit_sha",
    "target_head_revision",
    "risk_class",
    "test_evidence",
    "semantic_delta",
    "gate_verdict",
    "evaluated_at"
  ],
  "properties": {
    "task_id": { "type": "string" },
    "git_commit_sha": { "type": "string" },
    "target_head_revision": { "type": "string" },
    "risk_class": { "type": "string", "enum": ["Low", "Medium", "High", "Critical"] },
    "test_evidence": {
      "type": "object",
      "required": ["fail_to_pass_passed", "pass_to_pass_passed", "all_passed"],
      "properties": {
        "fail_to_pass_passed": { "type": "boolean" },
        "pass_to_pass_passed": { "type": "boolean" },
        "all_passed": { "type": "boolean" }
      }
    },
    "semantic_delta": {
      "type": "object",
      "required": ["files_changed", "summary", "spec_conformance"],
      "properties": {
        "files_changed": { "type": "array", "items": { "type": "string" } },
        "summary": { "type": "string" },
        "spec_conformance": { "type": "boolean" }

      "type": "string",
      "enum": ["AUTO_MERGE_APPROVED", "MANUAL_REVIEW_REQUIRED", "REJECTED"]

    "evaluated_at": { "type": "string", "format": "date-time" }

## 6. Agent Adapter Protocol

To remain agent-agnostic, `asdlc` uses an adapter interface:

```python
class AgentAdapter(abc.ABC):
    @abc.abstractmethod
    def name(self) -> str:
        """Returns the canonical adapter name (e.g. 'opencode', 'claude', 'mock')."""
        ...

    @abc.abstractmethod
    def run_turn(
        self,
        prompt: str,
        workdir: Path,
        trace_logger: Callable[[dict], None],
    ) -> int:
        """Executes one agent attempt against the workdir. Returns exit code."""
        ...
```

### Built-in Adapters:
1. **`MockAgentAdapter`**:
   - Deterministic test adapter. Replaces placeholder failure in `src/` with passing implementation on a specified turn. Allows fully offline, cost-free unit testing of the entire SDLC harness.
2. **`OpenCodeAdapter`**:
   - Invokes `opencode run "<prompt>"` in a subprocess.
3. **`ClaudeAdapter`**:
   - Invokes `claude -p "<prompt>"` in a subprocess.
4. **`AntigravityAdapter`**:
   - Invokes `agy --prompt "<prompt>"` in a subprocess.

## 7. Security & Guardrail Invariants

1. **Test Suite Immutability**:
   - Any modification to `tests/test_spec.py` by an agent during `asdlc tdd` triggers an immediate uncatchable `TestTamperingError` and aborts the run.
2. **Deterministic Halting**:
   - Agent execution stops strictly on `pytest` exit code 0 or reaching `--max-turns`. The harness does not ask the agent if it thinks it is done; the test suite is the sole arbiter.
3. **Outer Loop Isolation & Test Protection**:
   - In CI/CD, the workflow overlays or checks out test definitions directly from the target base branch (`main`), discarding any altered test definitions from the PR before running `pytest`.
   - `asdlc eval` enforces diff isolation: any PR attempting to modify files in `tests/` without `--allow-test-changes` is rejected (`gate_verdict = "REJECTED"`).

## 8. Verification & Test Matrix for `asdlc` Harness

The `asdlc` implementation will be verified by a pytest suite (`tests/test_asdlc.py`) covering:

| Test Case | Scenario | Expected Outcome |
| :--- | :--- | :--- |
| `test_init_creates_scaffold` | Run `asdlc init` on clean temp dir | Creates `.asdlc/`, `.gitignore`, `state.json` |
| `test_sdd_validates_intent` | Run `asdlc sdd` with valid/invalid `intent.md` | Passes on valid; raises error on missing required sections |
| `test_tdd_halts_on_green` | Run `asdlc tdd` with `MockAgentAdapter` | Starts RED $\to$ runs turn 1 $\to$ achieves GREEN $\to$ halts with code 0 |
| `test_tdd_detects_tampering` | Agent attempts to modify `tests/test_spec.py` | Detects SHA-256 mismatch $\to$ raises `TestTamperingError` $\to$ aborts |
| `test_tdd_max_turns_exceeded`| Agent fails to solve after max turns | Halts with code 1 after exactly $N$ turns, persists `ABORTED` |
| `test_tdd_fails_if_initial_tests_already_passing` | Initial tests pass before agent invocation | Halts and raises `InitialTestsAlreadyPassingError` |
| `test_adapter_subprocess_timeout` | Agent subprocess hangs | Times out after timeout duration and logs timeout |
| `test_eval_emits_valid_evidence` | Run `asdlc eval` on diff | Produces valid `release-evidence.json` matching JSON schema |
| `test_eval_rejects_tampered_test_diff` | PR diff contains modified files in `tests/` | Evaluator sets `gate_verdict = "REJECTED"` with security violation |
| `test_examples_hello_workspace_is_runnable` | Run `asdlc tdd` inside `examples/hello/` | Starts RED on buggy code $\to$ turns GREEN with mock adapter $\to$ exits 0 |
